# ADR 0053 — V4 governed definitions and material identification

Date: 2026-10-14. Status: implemented and locally verified as a V4 foundation checkpoint.

## Decision

Quality owns typed QMS Profile, Process, Policy and Requirement records in the existing database. `Forge:Qms:Organization` is explicit deployment configuration. No organization name, scope, applicability or policy approval is inferred. Registered users may discover configuration; record reads and transitions require current actual scope and source authority. Quality 0006 adds the governed model; Kernel 0008 adds the canonical role/permission seeds without assigning new roles to existing users. Kernel 0009 supplies common role authority and restores only migration-owned grants on pre-existing names. Total registered migration count is 91.

Each record has immutable organization/facility/program/marking ownership and numbered revisions. Draft content is editable with optimistic versions. Submit freezes content and exact source references; review and approval exclude every recorded author contributor. An independent reviewer may also approve. Effective revisions close the preceding interval exactly; supersession and withdrawal preserve content, source records and attributed history. Approved normative references retain their independent licensed-verification state.

QMS references existing Engineering document revisions and exact governed QMS revisions. Recorded classification and current owner classification both apply to reads and command retries. A later protected revision does not change the sources of an earlier exact revision. Obsolete historical document versions remain evidence; adopting them into a new effective definition requires a current valid source. Shared audit and notification projections delegate mixed source permissions to Quality. QMS facility ownership is resolved before evaluating facility-scoped audit permission; canonical audit bytes and hashes remain unchanged.

The action permissions are `quality.qms.read/manage/review/approve/publish`. Three author/reviewer/approver roles express these duties without granting physical release authority. Quality product acceptance uses the distinct `quality.product.release`; shipping retains its existing separate permission. Typed execution, product-release, label-copy and attempt-retention rules require explicit values. Recording a policy cannot weaken the pre-existing operational guards; dependent workflows must adopt a current approved exact policy rather than use invented defaults.

Host identification extends existing order/operation references with exact Inventory `(part, lot)` and location keys. Strict canonical UTF-8 percent encoding permits existing slash, percent and Unicode keys while rejecting aliases and malformed input. The 1,024-character encoded envelope supports 40-character owner keys. Current owner point queries avoid list caps. Material resolution returns identity metadata rather than inferring private stock/program details. Location access follows actual facility and work-center ownership.

Optional keyboard/manual scanning stages a preview and requires explicit selection. The existing material-pick transaction compares both scanned part and lot with the actual task. Null optional metadata is omitted from canonical JSON to preserve old fingerprints; supplied metadata binds retry. Current material-task authority is resolved before retry. UI generations clear delayed scans and selections after actor, context, dialog, terminal or availability changes. Server staging and label provenance remain the next increment.
